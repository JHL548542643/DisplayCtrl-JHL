# 安全模型

DisplayCtl 只对外接显示器写入允许列表里的 MCCS 码：亮度 `0x10`、对比度 `0x12`、音量 `0x62`，取值都是 `0..100`。写错屏幕、写错码、没读回来就当成功、或者在失败后连着补写，都比“这次没改成”更糟。所以默认动作是拒绝。

## 要挡住的事

| 风险 | 怎么挡 |
| --- | --- |
| 写到另一台屏 | 身份用 EDID 序列号或当前唯一的型号，不用 `\\.\DISPLAYn` 当主键。对不上就停 |
| 写到不该写的 VCP | 允许列表只有 `0x10` / `0x12` / `0x62`。`SetVCPFeature` 只有一个调用点，前面必过 `ensure_write_code` |
| 探测失败还硬写 | `vcp_ok` 不为真、刻度不是 100、身份不够，都不会调用写入 |
| 写入没生效还报成功 | 写完至少读一次。对不上就回滚一次，不再把目标值写第二遍 |
| 读也失败 | 停。不靠猜测再写一次 |
| 界面或脚本连点 | 每台屏间隔至少 0.8 秒，每分钟最多 12 次；全局每分钟最多 20 次。回滚不占第二次配额，避免限速把回滚本身吃掉 |
| 服务被局域网访问 | 进程只绑 `127.0.0.1`（或 `::1`）。其它地址直接退出 |

烧屏是另一类问题，不靠这个服务解决。这里防的是错误的 DDC 写入。

## 允许的 VCP

- 写入允许亮度 `0x10`、对比度 `0x12`、音量 `0x62`。`SetVCPFeature` 只有一个调用点，前面必过 `ensure_write_code`。
- `GetVCPFeatureAndVCPFeatureReply` 会读 `0x10`；在声明了已知安全码或 caps 过稀时，还可串行读已知安全码（本版 `0x12` / `0x62` / `0x16` / `0x18` / `0x1A` / `0x60` / `0xD6`）以取当前值。失败结果按身份缓存。
- 能力字符串在 `0x10` 读成功且按 EDID 身份的缓存未命中时读取，并缓存 5 分钟。解析结果用来取 `model(...)`、判断有没有声明，以及识别稀 caps。`0x10` 已经失败时不再读能力字符串，也不再探额外码。完整码表不会出现在 API 里。
- `capabilities.luminance` / `contrast` / `volume` 在安全管线允许时可以 `writable: true`，界面仍要确认后才写。`rgb_gains` / `input_source` / `power_mode` 即使可读也保持只读，没有写入接口。
- `0x04`（复位）、几何、输入源、色温、电源以及任何未列入写入允许列表的码，一律 `policy_blocked`。

常量在 `displayctl/policy.py`。

## 稳定身份

优先级：

1. **strong**：EDID 厂商 + 产品码 + 序列号（描述符里的文本优先，否则用非 0 的 32 位序号）。`stable: true`，可以写。
2. **model**：没有序列号，但 EDID 产品码或能力字符串里的型号在当前这次探测中只有一台。可以写，`stable: false`。再插一台相同型号后，两边都会变成冲突并停止可写。
3. **unstable**：没有 EDID，也没有型号。即使 `0x10` 能读，也不写。
4. **ambiguous**：上面的键撞车。行键会加上 `.dupN` 只为了让界面分得开，两台都不可写。

匹配句柄时：

- 两边都有合法 EDID，就只比 EDID。`\\.\DISPLAY1` 被系统改成 `\\.\DISPLAY4` 仍然打在同一块屏上。
- 只有一边有 EDID，视为不是同一台，放弃这次写入。
- 都没有 EDID 时，必须设备名、描述、矩形和主屏标志都相同。分辨率一变就拒绝，不猜。

CLI 的 `index` 只在这一次 `list` 的顺序里挑选，选中后立刻换成上面的 id。API 不接受“第几台”作为写入目标。

EDID 来自 Windows 显示设备的注册表块，不是另一个 VCP 读。优先用 `DeviceID` 对上 `Enum\DISPLAY\<id>` 里 `Driver` 与 `HardwareID` 都符合的那一份；对上多份且内容不同就当没有 EDID，而不是挑一份。类键只在枚举路径落空时再读。块头或校验和失败就当没有 EDID。

物理显示器句柄用完即 `DestroyPhysicalMonitors`，不跨请求缓存。

## 写入管线

`set_luminance_safe` / `set_contrast_safe` / `set_volume_safe(monitor_id, value, confirm=False)`：

1. `confirm` 不是布尔值 `True`：立刻拒绝，不探测。
2. 值不是 `0..100` 的整数（布尔值也拒绝）：立刻拒绝，不探测。
3. 拿硬件锁，重新探测全部物理屏的 VCP `0x10`（不用列表读数缓存）。能力字符串可以来自 EDID 缓存；`0x10` 失败时不额外读能力字符串。
4. 找不到 id、身份冲突、探测失败、不可写、最大值不是 100：拒绝，写入次数为 0。
5. 当前值已经等于目标：成功返回，`noop: true`，不写。
6. 通过限速器，记下这一次配额。
7. 打开句柄，按身份匹配到恰好一台，`SetVCPFeature(handle, <允许的 VCP>, value)` **一次**。
8. 等待 0.2 秒再读。最多读 2 次，中间再等 0.2 秒。第一次就已经一致就不再读。
9. 一致：成功。不再写。
10. 驱动报错且回读仍是原值，或根本读不到：`write_failed` / 按下面的“读不到”处理，不回滚。
11. 回读是别的数：把探测时的原值再写 **一次**。回读确认原值已回来，然后以 `verify_mismatch` 失败（屏幕应已回到原亮度）。回滚那一次写失败，或回滚后仍对不上：`rollback_failed`，到此停止。

没有第三笔写入，也没有“再把目标值试一次”。

## 失败分类

分类只决定提示和是否可写，不会因为“也许是线”就去写。

| kind | 何时 | 可写 |
| --- | --- | --- |
| `internal_panel` | 主屏且 `0x10` 读失败。内置屏优先于后面的判断，避免笔记本面板被说成 DDC 故障 | 否 |
| `transient` | Win32 121 / 170 / 258 / 1460，或能力字符串声明了 `10` 但这次没读到 | 否 |
| `ddc_off` | 外接、EDID 在、没有能力字符串、错误是 31 或没有错误码。链路能给 EDID，CI 命令失败，优先看 OSD 的 DDC/CI | 否 |
| `cable` | 外接、没有 EDID、也没有能力字符串、错误是 31 或没有错误码。EDID 和 VCP 都没有 | 否 |
| `unsupported` | 能力字符串里的 `vcp()` 明确没有 `10` | 否 |
| `unsupported_scale` | `0x10` 能读，但最大值不是 100，或当前值不在 `0..100` | 否 |
| `probe_failed` | 其它 Win32 错误 | 否 |
| `identity_ambiguous` | 身份键撞车 | 否 |
| `identity_unstable` | 能读亮度但没有 EDID/型号 | 否 |
| `confirm_required` | 没有明确确认 | 否 |
| `rate_limited` | 太密 | 否 |
| `verify_mismatch` | 已回滚成功 | 这次失败 |
| `verify_unconfirmed` | 写指令发出后读不到。没有第二笔 | 先看画面 |
| `rollback_failed` | 回滚没完成。先看 OSD，不要连点 | 停止 |

`ddc_off` 和 `cable` 是启发式。error 31（`ERROR_GEN_FAILURE`）单独分不出“OSD 关了 DDC/CI”和“线/扩展坞不透传”。分错类也不会导致写入。

`0x10` 失败且这个身份上没有缓存的能力字符串时，不再为了区分 `unsupported` 和「声明了 `10`」去读能力字符串。分类会落到 `internal_panel`、`ddc_off`、`cable` 或 `probe_failed`（瞬态 Win32 错误码仍然是 `transient`）。这些都不可写，写入次数仍是 0。缓存里已经有字符串时，仍用那份字符串做原来的判断。

主屏但 VCP 正常（外接屏被设成主显示器）可以写。不要把“主屏”一律当成内屏。

## 本机 API

- 默认 `127.0.0.1:8765`。`DISPLAYCTL_HOST=0.0.0.0` 或局域网地址会在监听前退出。
- 非回环来源的 HTTP 请求直接 403。
- `POST` 的 `confirm` 必须是 JSON 布尔值 `true`。缺省是 `false`。
- 没有登录。回环上的任意本机进程都能调用，所以确认标志和限速才是闸，而不是网络位置本身。
- 不要做端口转发，也不要把它挂到反向代理后面。那会绕开“只给坐在这台机器前的人用”这个前提。

## 明确不做

- Linux / macOS 后端。非 Windows 上库可以导入，真实探测会返回 `platform_unsupported`。
- 允许列表之外的 VCP 写入。GetVCP 除亮度外只允许已知安全码（本版 `0x12` / `0x62` / `0x16` / `0x18` / `0x1A` / `0x60` / `0xD6`）。其中对比度和音量可按上面的写入管线写；RGB、输入源、电源绝不调用 `SetVCPFeature`。
- 工厂复位、输入源切换、电源开关。
- 云端或远程控制。
- 未确认就写、探测失败自动重试、回读失败后再写目标值。
- 对同一台机器上的多块物理屏并行 `GetVCP` 或能力字符串。DDC/I²C 保持串行。

`--demo` 使用进程内的假显示器，供界面开发。它不会加载 dxva2。健康检查里 `demo: true`。

## 和最初那支 CLI 的差别

`brightness_vcp.py` 的子命令还是 `list` / `get` / `set`，`set` 没有 `--yes` 仍然打印 `refusing to change brightness without --yes` 并返回 3。枚举和 VCP `0x10` 的 Win32 调用方式没有改。

收紧的部分：

- 回读不一致会回滚一次，并以非 0 退出。旧脚本只把回读打印出来。
- 身份分不开、没有身份、或最大值不是 100 时拒绝。旧脚本按序号写 `0..100`。
- 同一进程里写太密会被拒绝。

退出码：`0` 成功，`1` 平台/没有显示器/序号或取值不合法，`2` 读取失败，`3` 没有 `--yes`，`4` 安全拒绝，`5` 回滚失败或写后无法回读。
